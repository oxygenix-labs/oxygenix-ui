# Input

A fundamental component for accepting user text input.

## Overview

The Input component is used to get user input in a text field. It supports various types including text, password, number, and more, along with validation states.

## Accessibility

- **Labeling**: Always use the `Input` component with a `label`. The easiest way to do this is with the `FormField` component.
- **Focus**: The focus ring is styled to be visible for keyboard users.
- **Error**: When in error state, consider adding `aria-invalid="true"` (handled by `error` prop).

## Props

| Prop | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `type` | `'text' \| 'number' \| 'password' \| ...` | `'text'` | HTML input type |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Size of the input |
| `error` | `boolean` | `false` | Visual error state |
| `className` | `string` | - | Additional CSS class |
| ... | `InputHTMLAttributes` | - | All standard input attributes |

## Common Mistakes

### Missing labels

Inputs must always have an associated label for accessibility. Do not rely solely on `placeholder`. Use `FormField` or connect a `<label>` with `htmlFor`.

### Type mismatch

Ensure you use the correct `type` for the data being collected. Use `type="email"` for emails and `type="tel"` for phone numbers to trigger the correct keyboard on mobile devices.
