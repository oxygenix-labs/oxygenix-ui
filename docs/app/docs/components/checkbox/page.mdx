# Checkbox

Checkbox component for boolean selections with support for indeterminate state and controlled grouping.

## Installation

```bash
npm install @oxygenix-ui/forms
```

## Basic Usage

```tsx
import { Form, Field } from '@oxygenix-ui/forms';

function TermsForm() {
  return (
    <Form onSubmit={(data) => console.log(data)}>
      <Field
        name="acceptTerms"
        label="I accept the terms and conditions"
        type="checkbox"
        required
      />
      <button type="submit">Continue</button>
    </Form>
  );
}
```

## Features

### Single Checkbox

Use for boolean yes/no selections.

```tsx
<Field
  name="newsletter"
  label="Subscribe to newsletter"
  type="checkbox"
/>
```

### Required Checkbox

Require users to check a box.

```tsx
<Field
  name="acceptTerms"
  label="I accept the terms and conditions"
  type="checkbox"
  required
  validate={(value) => {
    return value === true || 'You must accept the terms';
  }}
/>
```

### Indeterminate State

Implement indeterminate state with custom render.

```tsx
function SelectAllCheckbox({ items }) {
  const [selected, setSelected] = useState([]);
  
  const allSelected = selected.length === items.length;
  const someSelected = selected.length > 0 && selected.length < items.length;

  return (
    <div>
      <Field
        name="selectAll"
        label="Select All"
        render={({ field }) => (
          <input
            type="checkbox"
            checked={allSelected}
            ref={(el) => {
              if (el) el.indeterminate = someSelected;
            }}
            onChange={(e) => {
              if (e.target.checked) {
                setSelected(items.map(i => i.id));
              } else {
                setSelected([]);
              }
            }}
          />
        )}
      />
      
      {items.map(item => (
        <Field
          key={item.id}
          name={`item-${item.id}`}
          label={item.name}
          type="checkbox"
        />
      ))}
    </div>
  );
}
```

### Checkbox Group

Group related checkboxes.

```tsx
function PreferencesForm() {
  return (
    <Form onSubmit={handleSubmit}>
      <FieldGroup legend="Email Notifications">
        <Field
          name="emailComments"

        />
        <Field
          name="emailMessages"
          label="Direct messages"
          type="checkbox"
        />
        <Field
          name="emailUpdates"
          label="Product updates"
          type="checkbox"
        />
      </FieldGroup>
    </Form>
  );
}
```

## API Reference

### Field (Checkbox)

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `name` | `string` | Required | Field name |
| `label` | `ReactNode` | Required | Checkbox label |
| `type` | `'checkbox'` | Required | Must be 'checkbox' |
| `required` | `boolean` | `false` | Whether checkbox must be checked |
| `validate` | `ValidationFunction \| ValidationFunction[]` | - | Validation function(s) |
| `disabled` | `boolean` | `false` | Whether checkbox is disabled |
| `description` | `string` | - | Help text below the checkbox |

          name="canAdmin"
          label="Admin"
          type="checkbox"
          description="Full administrative access"

            }
            return true;
          }}
        />
      </FieldGroup>

    </Form>
  );

## Accessibility

The Checkbox component is fully accessible:

- **Labels**: Properly associated with checkbox
- **ARIA**: Full ARIA attribute support
- **Keyboard**: Space to toggle, Tab to navigate
- **Screen Reader**: State announced correctly
- **Focus**: Clear focus indicator

## Best Practices

### 1. Use Clear Labels

```tsx
// ✅ Good - clear action
<Field 
  name="newsletter" 
  label="Send me weekly newsletters"
  type="checkbox"
/>

// ❌ Bad - vague
<Field name="newsletter" label="Newsletter" type="checkbox" />
```

### 2. Provide Context

```tsx
// ✅ Good - explains what happens
<Field
  name="publicProfile"
  label="Make my profile public"
  type="checkbox"
  description="Others will be able to see your profile"
/>

// ❌ Bad - no context
<Field name="publicProfile" label="Public" type="checkbox" />
```

### 3. Group Related Checkboxes

```tsx
// ✅ Good - grouped logically
<FieldGroup legend="Notifications">
  <Field name="email" label="Email" type="checkbox" />
  <Field name="sms" label="SMS" type="checkbox" />
</FieldGroup>

// ❌ Bad - ungrouped
<Field name="email" label="Email notifications" type="checkbox" />
<Field name="sms" label="SMS notifications" type="checkbox" />
```

### 4. Use Radio for Exclusive Choices

```tsx
// ✅ Good - checkboxes for multiple selections
<Field name="interests" label="Interests" type="checkbox" />

// ❌ Bad - checkboxes for exclusive choice
<Field name="gender" label="Male" type="checkbox" />
<Field name="gender" label="Female" type="checkbox" />
// Should use radio buttons instead
```
