# Heading

Semantic heading component that enforces proper heading hierarchy.

## Overview

The Heading component handles titles and section headers. It bundles font sizing, weight, and line height while allowing you to strictly control the semantic HTML level (h1-h6).

## Accessibility

- **Level Order**: Always use heading levels in a descending order (h1 -> h2 -> h3). Do not skip levels (e.g., h1 to h3).
- **Navigation**: Screen readers use headings to allow users to quickly navigate mainly sections of the page.
- **Focus**: The component passes through props, so you can add `tabIndex` if a heading needs to be focusable.

## Props

| Prop | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `level` | `'h1' \| 'h2' \| 'h3' \| 'h4' \| 'h5' \| 'h6'` | **Required** | The semantic HTML heading level |
| `children` | `ReactNode` | - | Heading content |
| `className` | `string` | - | Additional CSS class |

## Common Mistakes

### Using headings for sizing only

Do not pick a `level` just because you like the font size. Always choose the `level` that represents the correct document structure. If you need a specific size but a different semantic level, use CSS or utility classes.

### Multiple H1 tags

A page should strictly have only one `h1` tag that describes the main topic of the page. Use `h2` through `h6` for sub-sections.
